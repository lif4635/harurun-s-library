# 全頂点の部分木を追加・削除で集計する

## 主な機能

頂点を1つ追加・削除する処理を用意すると、すべての頂点について部分木の集計を求められる。たとえば「部分木に含まれる色の種類数」「部分木で最も多い色の出現回数」に使う。

`DSUOnTree(tree, root)`は、木の隣接リストから頂点の処理順をO(N)時間・領域で準備する。集計値そのものは保持しない。`run`へ渡す関数で集計を更新する。

- `add(v)`: 頂点vの情報を集計へ加える。
- `remove(v)`: 頂点vの情報を集計から取り除く。
- `query(v)`: 集計対象がvの部分木と一致した状態で、vの答えを保存する。

`query`は各頂点で1回、`add`・`remove`は合計O(N log N)回呼ばれる。各関数がO(1)なら全体O(N log N)。各関数が重い場合は、その呼出し回数に処理時間を掛ける。単純な部分木和なら、Euler順とBITの組合せも選べる。

## 使い方

各部分木にある色の種類数を求める。

```python
tree = [[1, 2], [0, 3, 4], [0], [1], [1]]
color = [0, 1, 0, 1, 2]
solver = DSUOnTree(tree)
count = [0] * 3
distinct = [0]
answer = [0] * len(tree)

def add(v):
    c = color[v]
    if count[c] == 0:
        distinct[0] += 1
    count[c] += 1

def remove(v):
    c = color[v]
    count[c] -= 1
    if count[c] == 0:
        distinct[0] -= 1

def query(v):
    answer[v] = distinct[0]

solver.run(add, query, remove)
```

- `answer`: 頂点番号順の答え。この例では`[3, 2, 1, 1, 1]`。
- `run`の返り値: `None`。答えは`query`内で保存する。
- `euler`: 重い子を先にたどった頂点の配列。vの部分木は半開区間`[down[v], up[v])`を占める。

## 仕組み

子のうち、頂点数が最大の部分木の集計を残す。他の子の部分木は、必要なときだけ加え直す。頂点が加え直されるたびに対象の部分木は少なくとも約2倍になるため、1頂点あたりO(log N)回の追加・削除で済む。

重い子を先に並べた`euler`を逆から読むことで、再帰や`run`用の状態スタックなしで処理する。`run`自体の追加領域はO(1)。集計用の配列・データ構造の領域は別に必要になる。

## 注意点

- 木は空でない無向木。各辺を隣接リストの両端へ登録し、重み付きtupleは渡さない。
- 開始時の集計は空にする。終了時は根の部分木、つまり全頂点が集計に残る。同じsolverでもう一度`run`するなら、自分の集計を空に戻す。
- 頂点番号順・兄弟の順など、callbackを呼ぶ順序は保証しない。`query(v)`時にvの部分木だけが集計対象になっていることを利用する。
- `reset()`は軽い子の部分木をすべて削除したあとに呼ぶ。`remove`の代わりではなく、空になった集計の補助情報を掃除したい場合に使う。省略できる。
- `add`・`remove`・`query`・`reset`の返り値は使わない。
