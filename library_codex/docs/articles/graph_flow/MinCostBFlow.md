# 供給・需要と流量上下限のある最小費用流

各頂点の供給・需要と各辺の流量上下限を守り、流した量×単位費用の合計を最小にする。

## 主な機能

- `MinCostBFlow(n)`に辺`(始点, 終点, 流量下限, 流量上限, 単位費用)`と頂点の供給・需要を登録する。
- `run()`で実行可能性・最小費用を求め、`get_flow(i)`で各辺の流量を取得する。負の費用・負の流量下限・自己ループに対応する。
- 整数費用のcost scalingを使う。一般の最悪上界は`O(V²E log(VC+2)+V+E)`、追加領域は`O(V+E)`。`C`は単位費用の絶対値の最大。

## 使い方

```python
g = MinCostBFlow(3)
g.add_supply(0, 4)
g.add_demand(2, 4)
g.add_edge(0, 1, 1, 5, 3)
g.add_edge(1, 2, 0, 5, -1)
feasible, cost = g.run()
flows = [g.get_flow(i) for i in range(2)] if feasible else None
```

- `feasible`: 全制約を満たせるか。この例では`True`。
- `cost`: 最小費用。この例では`8`。実行不可能な場合の`0`は最適値ではない。
- `flows`: 辺の追加順の流量。この例では`[4, 4]`。
- `g.dual[v]`: 最適性の確認に使える頂点ごとのポテンシャル。通常は流量と費用だけ読めばよい。

## 供給・需要の意味

`add_supply(v, b)`は、頂点`v`の「流出量−流入量」に`b`を加える。`add_demand(v, b)`はその値から`b`を引く。供給・需要を指定しない頂点では流入と流出が一致する。

辺の費用を`c`、始点を`u`、終点を`v`、ポテンシャルを`p`とすると、残余辺の費用は次の形で確認できる。

$$c+p_u-p_v$$

- 流量を増やせる辺では、この値が非負。
- 流量を減らせる辺では、この値が非正。

## 注意点

- 容量境界・費用・供給・需要には整数を使う。下限は上限以下にする。
- `run()`は一度だけ呼ぶ。呼出し後には辺・供給・需要を追加できない。
- 流量・ポテンシャルは`feasible`が`True`のときだけ解として利用する。
- 始点・終点だけを指定して最大量を送るAPIではない。送りたい量を供給・需要として指定する。
