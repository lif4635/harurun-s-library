# k辺最短路の計測

2026-09-07、WSL Ubuntu / PyPy 3.10.14 (7.3.16)。各実装を小さい入力で3回実行後、対象入力を3回実行した中央値。並列実行はしない。旧実装の辺数別DPを比較用スクリプト内に残している。

| 重み | N | k | 旧実装 | 新実装 |
| --- | ---: | ---: | ---: | ---: |
| `(j-i)**2` | 2000 | 1000 | 0.635秒 | 0.00171秒 |
| `(j-i)**2` | 8000 | 4000 | 11.605秒 | 0.00529秒 |
| `(j-i)**2 + ((j*7919)%2001-1000)` | 2000 | 1000 | 0.776秒 | 0.00586秒 |

二乗コストの答えは区間長をできるだけ均等にした閉形式、偏りのあるコストは旧実装と比較した。倍率は入力に依存し、一般的な速度保証ではない。小さいkや巨大な整数では辺数別DPへ切り替えるため、これほどの差は出ない。

```sh
pypy3 library_codex/benchmarks/monge_shortest_paths.py
pypy3 library_codex/benchmarks/monge_shortest_paths.py --sizes 2000 --biased
pypy3 -m pytest -q library_codex/verify/optimization/test_monge_shortest_paths.py
```

専用テストはMonge行列を生成し、全てのkの答えを三重ループのDPと照合する。負の重み、ペナルティの正負、同点で辺数が飛ぶ場合、巨大整数、非整数用DP、境界値、重み関数の呼出し回数、配布用コードの単独実行を検査する。

## 二分探索と黄金分割探索の比較

2026-09-07、同じPyPy環境で比較。公開実装は二分探索を維持する。黄金分割探索の候補は比較用スクリプトだけに残し、公開APIは増やさない。

ペナルティを `p`、辺数制限なしの最短距離を `D(p)` とすると、`D(p) - k*p` は凹関数になる。二分探索は最短路の辺数も求めて探索方向を決める。黄金分割探索は関数値だけを使い、整数の探索区間をフィボナッチ数で縮める。どちらもペナルティの探索幅に対して対数回の最短路計算だが、1回の負担と必要な回数が異なる。

比較は次の2通り。

- `binary_bounded` / `golden_bounded`: 同じ既知の探索範囲を与える。範囲は各入力の最適ペナルティを含むように設定する。
- `binary_auto` / `golden_auto`: 範囲を与えず、指数的に広げて探索する。公開APIと同じ用途。両方とも最短路計算をk回まで試し、それで終わらなければ同じ辺数別DPへ切り替える。

対象入力で各方式を3回ウォームアップし、実行順を交代して7回測定した中央値。重み関数の呼出し回数は計時とは別に測る。単一プロセスで実行し、別プロセスでの再測定でも全体の傾向を確認した。

以下は N=4096 の自動範囲探索。kは通常2048、小さいkの行は7、不均一な間隔の行は1365。

| 重み | 二分探索 | 黄金分割探索 | 二分探索の重み呼出し数 | 黄金分割探索の重み呼出し数 |
| --- | ---: | ---: | ---: | ---: |
| `(j-i)**2` | 5.820 ms | 8.239 ms | 102,348 | 249,700 |
| `(j-i)**2`、小さいk | 26.299 ms | 19.932 ms | 898,255 | 898,255 |
| 二乗コスト＋頂点ごとの偏り | 21.898 ms | 32.319 ms | 278,755 | 558,078 |
| 二乗コスト＋1,000,000 | 68.938 ms | 132.509 ms | 2,007,957 | 2,598,795 |
| 二乗コスト−1,000,000 | 60.451 ms | 116.934 ms | 1,476,737 | 2,076,875 |
| 全辺0 | 5.978 ms | 5.273 ms | 90,099 | 90,099 |
| 二乗コスト×10の30乗 | 551.589 ms | 1055.030 ms | 3,377,848 | 8,756,196 |
| 不均一な間隔の累積値の差の二乗 | 34.459 ms | 68.700 ms | 539,871 | 898,331 |

黄金分割探索が常に遅いわけではない。既知範囲の N=4096 の二乗コストでは、二分探索65.269 msに対して黄金分割探索49.531 ms、頂点ごとの偏りを加えた場合も79.648 msに対して75.282 msだった。一方、自動範囲探索では通常の二乗コスト、偏り、正負の大きなペナルティ、巨大整数、不均一な間隔で二分探索が速かった。N=512でもこれらの傾向は同じだった。

小さいkでは両方式とも辺数別DPへ切り替わっており、表の差は黄金分割探索の優位とは判断しない。同点の多い入力では黄金分割探索が少し速かったが、公開API全体を置き換える根拠にはしない。測定時間にはPyPyの最適化や実行状態の影響もあるため、全入力での優劣は保証しない。

正しさは、負の重みも含むランダムMonge行列で N=1〜23 の全てのkを単純DPと照合する。整数の黄金分割探索そのものについても、探索区間外に頂点がある場合や平坦な最大値を持つ凹関数を全探索と照合する。専用テストは12件成功。

```sh
pypy3 library_codex/benchmarks/monge_penalty_search.py
pypy3 library_codex/benchmarks/monge_penalty_search.py --sizes 4096 --repeat 7
pypy3 -m pytest -q library_codex/verify/optimization/test_monge_shortest_paths.py
```
