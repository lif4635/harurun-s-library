2026-11-16。PyPy 7.3.16、WSL2、CPU 2へ固定し、各方式を新しいprocessで5回ずつ測定した。方式の順を入れ替え、入力・答えのSHA-256一致を確認している。CPUの占有はしていない。下表はライブラリ計算部分の中央値で、起動・JITを分離した定常性能の測定ではない。

## 採用と不利な条件

- max-minは値順に添字を有効化する部分を共有し、NTTで存在を確認する方式とPython整数bit集合を比較した。測った最大長32768ではbit集合が約2.97倍速かった。ただし計算量はO(L²/w)を含み、任意の巨大入力でNTT方式より速いことは示していない。
- 添字制約付き畳み込みは、初期の小さい分割幅では4096要素で0.048497秒かかり、二重ループより遅かった。寄与する係数対が8388608個以下、または短い列が32要素以下なら直接計算する。大きい入力の葉の幅は512とした。32768要素では初期案0.144933秒から0.104923秒へ短縮した。
- 4096要素の採用版は入力の正規化も行うので、正規化済み入力だけを扱う比較器より約11%遅い。小規模の全条件で優位とはしない。
- 区間mapは小規模ではlistより遅い。大きい座標・多数の区間へのオンライン代入が用途であり、短い配列を置き換えるための構造ではない。削除済みTreap領域の回収を有効にしたまま測っている。
- 暗黙Dijkstraは全状態に到達する格子では時間・RSSとも通常版に負けた。辞書の負担があり、既存の通常版は置き換えない。未訪問の辺を生成しなくてよいこと、状態に整数IDを振らなくてよいこと、終点条件で途中終了できることが追加機能である。
- 個数指定部分和は圧縮後の和の範囲に依存する。多法NTTを使う参照実装との速度比較は未実施。

## 再実行

リポジトリ直下から、測定役はLinux CPython、実行対象はPyPyを指定する。CPU番号は使用できるものへ合わせる。

```sh
/usr/bin/python3 library_codex/benchmarks/reference_algorithms.py --python /path/to/pypy3 --repeat 5 --cpu 2
```

`--cases ordered ordered-large`のように対象を指定できる。一部だけ測るときは`--output`で別の保存先を指定し、全ケースの記録を上書きしない。
