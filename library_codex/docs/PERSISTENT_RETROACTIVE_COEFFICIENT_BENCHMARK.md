# 永続構造・遡及キュー・遠い係数のPyPy比較

2026-11-16。PyPy 7.3.16、WSL2、Ryzen 7 3700XのCPU 2へ固定。各方式を新しいprocessで5回ずつ、順番を入れ替えて順次実行した。CPUは占有していない。C++・Nimとの時間比較ではない。

各回の時間、起動込み時間、最大RSS、入力・結果・sourceのSHA-256は[測定JSON](../../verify/library_checker/benchmarks/comparisons/persistent-retroactive-coefficients.json)に保存した。全比較で入力と結果のhashが一致した。以下は構築と操作を含む中央値で、process起動と結果hashの作成は時間から除く。RSSはprocess全体。

## 比較器と範囲

- 永続列は既存`PersistentString`の一点置換・両端操作と比較した。各反復の結果の版を保存し、代入では古い版と更新版の両方を読む。両端操作の比較器は削除直後の中間版を保持しないが、採用版は中間版も内部に保持するため、時間・RSSにはこのAPI上の差も含む。一点代入では3倍以上速いが、両端操作だけでは約11%遅く、保存量も増える。分割・自己連結の正しさと巨大な共有列は専用testで検証したが、この表はそれらの速度比較ではない。
- 永続動的木は既存`LinkCutTree`の配列を操作ごとに全コピーし、全版を保持する方式との比較。初期森は一本の道で、両端の経路和を照会する。通常の非永続LinkCutTreeとの等機能比較ではない。古い未調整版へ戻るケースでは約4.4倍遅く、メモリも多い。任意分岐へ償却O(log² N)を主張しない。
- 遡及キューは、各編集後に全時刻をheapqで再実行する方式との比較。各回で最優先値・総和・取り出された総和・個数を照合。大きいケースは約2.4倍速いが、32スロットでは約1.5倍遅い。過去編集がない通常heapの置換にはしない。
- 係数取得は既存`SparseFormalPowerSeries`で必要次数まで計算して最後の値を取る方式と比較。冪の指数は10の9乗、法は998244353。逆数の入力は`1+3x+7x^31`、expは`3x+5x^2`、冪は`1+3x+5x^2`。最大次数依存と非零項数依存を混同しない。
- 1000万次ではexpが約1.11倍、冪が約1.31倍速い。RSSはそれぞれ約58%・68%減った。小さい次数の差は誤差も含み、同じ疎漸化式を使うため高速化の成果とは扱わない。

## 不採用案と切替

初稿はexp・冪の65次以上へ平方分割を使っていた。100万次でexp約0.19秒・冪約0.20秒となり、既存の疎漸化式約0.05秒・0.08秒より遅かった。最終版では200万以下を疎漸化式に戻した。これは測定した環境・入力での選択で、全次数・全入力に最適な閾値という保証はない。

初稿は`benchmarks/baselines/sparse_coefficient.py`へ保存し、最終の比較scriptでも`initial`として同じ入力で再測定している。[最初の比較](../../verify/library_checker/benchmarks/comparisons/persistent-retroactive-coefficients-initial.json)と[遠い係数の追加測定](../../verify/library_checker/benchmarks/comparisons/persistent-coefficient-far.json)も残した。

## 再実行

```sh
/usr/bin/python3 library_codex/benchmarks/persistent_retroactive_coefficients.py --python /path/to/pypy3 --repeat 5 --cpu 2
```

`--cases tree-branch coeff-exp-far`などで対象を絞れる。単純解とのランダム照合、入力境界、版の保持、非可換経路積はsource categoryに対応する専用testに置いている。オンラインjudgeへの提出結果ではない。
