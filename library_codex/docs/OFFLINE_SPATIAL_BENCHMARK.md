# 区間k番目の一括処理と点列挙の比較

2026-11-16。PyPy 7.3.16、WSL2、CPU 2へ固定。各方式を新しいprocessで5回実行し、順番を入れ替えて入力・結果のSHA-256一致を確認した。CPUは占有していない。C++・Nimとの実行時間比較ではない。

再実行scriptは`library_codex/benchmarks/offline_spatial_queries.py`。[測定JSON](../../verify/library_checker/benchmarks/comparisons/offline-spatial-queries.json)に各回の時間、起動込み時間、最大RSS、環境、入力とsourceのhashを保存している。下表は構築と操作を合わせた中央値で、起動時間は含まない。JITの初回コストは含む。

## 区間k番目

比較器は既存の`WaveletMatrix`。双方とも値の座標圧縮を含む。問い合わせは全て静的な半開区間に対するもの。

| 入力 | WaveletMatrix 秒 | OfflineRangeKth 秒 | 最大RSS KiB: 比較器 / 採用版 |
| --- | ---: | ---: | ---: |
| 64要素・64件 | 0.000564 | 0.000431 | 74940 / 75088 |
| 50000要素・50000件、乱数 | 0.219956 | 0.052002 | 101264 / 98024 |
| 50000要素・32件 | 0.046404 | 0.033799 | 97052 / 87056 |
| 50000要素・50000件、16種類の値 | 0.096447 | 0.021169 | 93924 / 91264 |
| 50000要素・50000件、昇順 | 0.174955 | 0.009170 | 103096 / 90488 |

一般の乱数入力では約4.23倍速かった。昇順入力は並べ直す必要がないため、直接値を返す。後から問い合わせる用途や頻度・前後の値の検索には既存WaveletMatrixを使う。bit圧縮された既存実装に対し、全入力で省メモリになるとは主張しない。

## 点列挙

比較器は、x順の葉にyを置き、区間最小値で枝刈りする最小値セグ木。双方とも固定x座標・一点y代入・条件を満たす点IDの列挙を行う。`LazyKDTree`は座標の動的変更と同じ列挙APIを持たないため、比較器にはしていない。

| 入力 | 最小値セグ木 秒 | PrioritySearchTree 秒 | 最大RSS KiB: 比較器 / 採用版 |
| --- | ---: | ---: | ---: |
| 32768点・4096操作、y上限32 | 0.080090 | 0.130341 | 84592 / 86364 |
| 8192点・128操作、出力多数 | 0.025829 | 0.039320 | 84980 / 85340 |
| 32768点・4096操作、x幅8 | 0.073031 | 0.126936 | 84968 / 88560 |
| 65536点・全範囲4096回、y上限64 | 0.147055 | 0.105423 | 98752 / 100664 |

最初の3ケースは3操作に1回のy更新を含む。最後は更新なしで全範囲を繰り返し列挙する。点IDの順序を揃えるsortは計算時間の外で行い、最大RSSには含む。

- 全範囲から少数の点を列挙するケースでは約1.39倍速い。出力数Kに対するO(log N+K)の保証を持つ選択肢として追加した。
- 更新混在・狭い区間では比較器より遅く、最大RSSも大きい。通常の最小値セグ木や既存構造の置換は行わない。
- 初稿のnode・区間tupleによる探索を、整数node番号による境界探索へ変更した。初稿との比較では狭い区間が0.162914秒から0.126936秒になった一方、疎な出力の更新混在では0.123095秒から0.130341秒と悪化した。全ケースでの改善ではない。
- 無効な点はposition配列で判定し、整数のy配列にNoneを混ぜない。これだけの独立した速度向上は確認できていない。

初稿は`benchmarks/baselines/priority_search_tree.py`に保持し、比較scriptの`initial`で実行する。[最初の測定](../../verify/library_checker/benchmarks/comparisons/offline-spatial-queries-initial.json)と[境界探索を変更した段階](../../verify/library_checker/benchmarks/comparisons/offline-spatial-queries-traversal.json)も残している。

## 再実行

PyPyの専用テスト7件と、記事のコードを単独bundleで実行するテストを含め、全体で1373件が成功した。オンラインjudgeへの提出結果ではない。
