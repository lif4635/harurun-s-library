# BinaryTrieの軽量化と計測

2026-09-29、WSL Ubuntu / PyPy 3.10.14 (7.3.16)。旧実装は変更前のsourceを比較専用の `benchmarks/_binary_trie_baseline.py` に固定した。

## 採用した構造

通常版を圧縮BinaryTrieへ置き換えた。ノードはclassではなく整数IDで管理し、左右の子・分岐ビット・代表キー・個数を平坦な配列へ保存する。削除時は不要な葉と分岐を取り除き、その領域を再利用する。

異なるキーD個に対して生きているノードは2D−1個。確保済み領域は現在のDではなく、過去に同時保持した異なるキー数の最大値に比例する。空き領域はOSへ返すのではなく、次の追加で再利用する。

`BinaryTrieMonoid`は独立した実装とし、通常版へモノイド用配列・callback・分岐を追加しない。非可換モノイドはキーの昇順で集約する。キーの全体XORは可換モノイドに限定する。

## 通常版の時間

各入力は2万要素。方式ごとに別processで小さい入力を3回ウォームアップし、7回計測した中央値。2回の独立した実行で傾向も確認した。値の生成・GCは計時外。全ての入力で検索結果のchecksumが旧実装と一致した。

- 構築：2万回のadd。
- 検索：各2万回のxor_min・kth・bisect_left。
- 更新：元の値を1個削除してランダムな値を1個追加する操作を2万回。
- 「連続整数」「重複」「共通prefix」は構築時の分布。更新後はランダムなキーへ置き換わる。

各欄は旧実装 → 圧縮版、単位はms。

| 入力 | 構築 | 検索 | 更新 |
| --- | ---: | ---: | ---: |
| ランダム30bit | 39.734 → 13.717 | 44.777 → 18.177 | 78.536 → 21.086 |
| 連続整数 | 7.923 → 13.314 | 15.867 → 12.490 | 60.031 → 20.824 |
| 128種類の重複 | 3.064 → 2.915 | 12.208 → 4.138 | 48.454 → 21.698 |
| 共通prefix、下位16bit | 8.858 → 11.984 | 18.224 → 11.583 | 58.989 → 23.950 |
| ランダム60bit | 90.514 → 13.171 | 71.530 → 19.600 | 155.560 → 18.947 |

連続整数や共通prefixの構築だけは遅くなる。全入力での改善とはしない。疎なキー・検索・削除と再挿入での改善を理由に圧縮版を採用した。

## 領域

list要素数は配列の論理要素数の合計であり、byte数やPython object数ではない。内部配列の余剰容量も含めない。

| 入力 | 構築直後のlist要素数：旧 → 新 | 更新後のlist要素数：旧 → 新 | processのpeak RSS：旧 → 新 |
| --- | ---: | ---: | ---: |
| ランダム30bit | 1,007,802 → 199,985 | 1,897,170 → 199,995 | 105.80 → 75.96 MiB |
| 連続整数 | 120,060 → 199,995 | 1,129,158 → 199,995 | 106.67 → 74.94 MiB |
| 128種類の重複 | 834 → 1,275 | 1,009,422 → 199,995 | 101.90 → 78.54 MiB |
| 共通prefix | 177,369 → 171,395 | 1,185,921 → 199,995 | 104.95 → 77.41 MiB |
| ランダム60bit | 2,809,014 → 199,995 | 5,498,205 → 199,995 | 146.68 → 75.92 MiB |

RSSは時間測定とは別processで、同じ構築・検索・更新を一度行った全processの最大値。PyPy本体・JIT・入力列も含み、データ構造単体の使用量ではない。密な値だけを保持する場合は、ノード当たりの項目が増える圧縮版の方が大きくなる場合もある。

## モノイド版

ランダム30bitの異なるキー2万個、演算は整数加算。既存DynamicSegmentTreeと比較した。各方式を別processで3回ウォームアップ後、7回計測した中央値。構築2万回、区間積2万回、既存キーの値の上書き2万回。区間積のchecksumは一致した。

| 実装 | 構築 | 区間積 | 上書き | 確保ノード数 |
| --- | ---: | ---: | ---: | ---: |
| DynamicSegmentTree | 59.053 ms | 41.306 ms | 26.732 ms | 336,245 |
| BinaryTrieMonoid | 16.204 ms | 26.273 ms | 9.210 ms | 39,999 |

和だけの計測なので、重いopや他のキー分布まで同じ倍率を保証しない。文字列連結による非可換の順序、全体XOR後の更新・積、単位元を値にしたキー、削除領域の再利用は専用testで検査する。

## APIと保守

- 通常版の本来のmethod名は維持する。`insert`・`count_of`・`erase`・`apply_xor`という互換aliasは削除した。`add`・`count_value`・`discard`・`xor_all`を使う。
- 範囲外のadd・xor_allはValueError。count_valueは範囲外なら0。bisect_leftは負数や上限を超える比較値にも対応する。
- tolistはkthの繰返しをやめ、重複込みの要素数Nに対してO(N)で列挙する。
- SternBrocotNodeは境界・LCA・constructorなどの説明を修正。深さを保持し、depthをO(1)、go_parentを取り除く圧縮経路の要素数Kに対してO(1 + K)にした。
- trie・平衡二分探索木の定数倍、時間とメモリの比較、通常版へ集約機能の負担を加えない方針をAGENTS.mdとCONTRIBUTING.mdへ追加した。全BBSTの実装を変更したわけではない。
